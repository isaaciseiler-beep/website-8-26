# Motion audit and implementation plan

Date: October 31, 2026. Scope: the Desktop checkout, current working tree on `main`, preview at `http://127.0.0.1:8080`. Planning only; application code has not been changed for this audit. Existing uncommitted UI/content changes are part of the inspected baseline and must be preserved.

Implementation: see [the completed changes and verification record](motion-verification-2026-10-31/README.md). The audit findings below describe the pre-implementation state.

## Direction

Make motion express continuity, hierarchy, and response. The strongest moment should be the Explore surface opening into a useful interactive view. Navigation should feel direct, photographs should settle quietly, and reading should remain steady. Each interaction gets one principal movement; supporting elements may fade within it. Text remains sharp and full size.

Preserve the quiet homepage, original header/sidebar, normal scrolling, Satoshi, Lucide outlines, 7px site corners, and the faint inset recess. Resting Explore remains flat. Hover/focus depth remains clipped to the compact form until results exist. Retain the initial photography limit, permanent gallery, alternating album pairs, location-only captions, and stable per-document photo order. No new intro, decorative scroll choreography, or live photo/classroom AI layouts.

## What to keep

- Explore's measured inner container, retained state, draft/commit distinction, pending-response cancellation, inert/hidden exiting content, and staged Clear collapse.
- Autocomplete in normal form flow, with its accessible combobox behavior and immediate dismissal paths.
- Suggestion text's measured footprint, opacity crossfade, hover/focus pause, visibility pause, and reduced-motion pause (`HomeExplore.tsx:110`).
- Work's restrained image/caption treatment and touch-visible titles. Photo captions remain known locations only.
- The shared non-bouncing easing curves, keyboard focus, native select behavior, and page scroll restoration.
- Static Writing placeholder and simple document/contact views. They do not need an additional animation to justify their presence.

## Proposed motion score

Use current token roles first. These are starting targets for browser tuning, not a claim that every interaction should use an identical duration. Any new exit/feedback role belongs in the owning motion definitions, not scattered literals. The AI theme retains its named small/large values unless a coordinated token change is necessary.

| Role | Proposed behavior | Starting timing |
| --- | --- | --- |
| Feedback | Color/opacity response; selected state updates immediately; no delayed action | 160–220ms shell; existing 200ms AI small role |
| Small disclosure | Content follows measured height; supporting opacity starts within the same sequence | Existing 200/360ms AI roles; 160ms exit where appropriate |
| Navigation | Panel and page respond together; labels stay crisp; no item-by-item blur | 340ms shell opening, approximately 220ms closing |
| Route handoff | Short exit and clean arrival, without a second full-page reveal | Approximately 120ms exit + 220ms entrance; readiness governs loading |
| Explore expansion | Width starts with the request's local result; measured height follows continuously; result detail fades in within expansion | Existing 360ms width / 460ms measured height, opacity 200–240ms; tune as a single sequence |
| Explore Clear | Detail fades, vertical space folds, then compact width releases | Retain 460ms fold as initial baseline; avoid extra idle delays |
| Photo interaction | Caption fades over a stable image; restrained optional image settle | 220–340ms; existing subtle image scale only |
| Image navigation | Decode-aware image transition over a stable backdrop | Approximately 220ms; no repeated overlay entrance |
| Data update | Change the affected bars/marks/detail only; labels and controls stay readable | Existing AI large role, bounded; static final state under reduced motion |
| Theme | One controlled color/snapshot transition | Approximately 220ms; immediate under reduced motion |

Compelling motion comes from the relationship between states: the Explore bar visibly becomes the result surface, a changed selection updates its adjacent evidence, and image browsing maintains visual continuity. Avoid adding bounce, overshoot, text scaling, exterior glow, magnetic buttons, or a site-wide parallax effect.

## Implementation sequence

1. **Establish the baseline and contract.** Capture normal/reduced-motion sequences at desktop and narrow widths, light/dark; record current timings and frame traces. Assign ownership of each transition, keep AI theme scope, define interruptible entrance/exit behavior, and create a shared preference policy for non-Motion engines. Preserve all existing edits. Deliverable: documented motion roles and baseline recordings.
2. **Make the shell coherent.** Coordinate menu, Search, page offset, and route handoff. Remove nested blur/scale text entrances; keep the original header/sidebar geometry and blend behavior. Shorten closing motion. Make outgoing content inert/hidden at the correct lifecycle point without breaking focus restoration. Replace double theme animation. Deliverable: navigation and theme sequences that feel like one system.
3. **Make Explore the signature interaction.** Coordinate width, measured height, detail opacity, and loading without introducing artificial waiting. Keep committed results while drafting/loading. Animate changed regions rather than whole modules. Preserve autocomplete flow, history, state, focus, IME, and Clear sequencing. Deliverable: comparison, Taiwan, career, work explorer, and project Back flows.
4. **Refine photographic continuity.** Replace cover flash cycling, stabilize hover preview order, stage decoded lightbox images, retain controls through navigation, and coordinate album entry/return with scrolling. Preserve seams, columns, touch captions, and album order. Deliverable: gallery → album → viewer → return that works equally with pointer and keyboard.
5. **Bring editorial/data/special routes into the system.** Reduce nested long-form reveals, disable reduced-motion parallax/chart animation, unify map camera policy and panel motion, audit Music hover/focus, and suspend unnecessary arcade/background loops. Keep decorative legacy effects off the main experience. Deliverable: consistent deep-page behavior without flattening data or game interactions.
6. **Verify and tune from recordings.** Review normal speed and slow playback, interruption, cold loads, rapid input, and theme changes. Use frame/layout/paint traces to resolve actual costs. Change timings only when the sequence evidence justifies it; run focused regression checks and build after the final edit. No publish or push in this scope.

## Acceptance criteria

- One clear visual focus per interaction. No duplicate route/page/image reveal for the same arrival; no blurred or scaled reading text.
- Normal scrolling throughout; no horizontal overflow or controls escaping the AI window at narrow widths. The composer stays vertically anchored while results expand below it.
- Rapid reversals continue from the current visual state. No stale image/provider result, delayed focus jump, blank suggestion frame, or stranded half-collapsed panel.
- Reduced motion removes autonomous photo changes, scroll-linked decoration, essential camera flights, chart animation, theme animation, and explicit smooth scrolling. Content and state remain immediately usable.
- Loading represents actual work. Keep useful content visible; show a restrained status only for genuine waiting. No fake progress or minimum-duration delays.
- Preserve semantic/accessibility lifecycles: exiting content inert/hidden, focus visible and restored, IME and keyboard selection intact.
- Record frame behavior on representative desktop/mobile-size sessions. Target smooth frame pacing; investigate long frames and repeated full-page layout/paint. Do not claim improvement from token cleanup or screenshots alone.
- Run the five focused Vitest files in AGENTS.md and `npm run build`; inspect generated feed/sitemap changes separately. Keep preview available. Do not deploy or push without a request.

## Verification limits

This is an audit and plan, not a completed motion refactor. Source inspection covered the motion systems and route families above; browser sampling used the existing local Chrome preview. Narrow/touch emulation, live reduced-motion behavior, frame traces, exhaustive preset rendering, configured map playback, and production/provider behavior were not measured in this planning pass. Mapbox's missing-token screen was observed directly. No tests/build were run because no application code was changed. No performance improvement is claimed.
