# seiler.page GenUI coverage and interaction review

Target: `isaaciseiler-beep/website-8-26`, the repository configured for **https://seiler.page**. Work was performed in the Desktop checkout on November 2, 2026. The review is local; nothing was pushed or deployed.

## Findings and changes

The six public projects were already enumerated, but provider context clipped sections to their opening 650 characters and omitted source labels, statistics, quotes, and media context. Local routing mostly recognized project names and a few familiar topics. The renderer could also replace a correctly selected later section with the first section in a focus group, or replace a contribution passage with the same project overview. These independent effects made the experience appear much narrower than the source material.

The providers now receive the complete published case-study corpus, and the renderer supports validated section and paragraph references. Local discovery searches full paragraphs, bullets, quotes, statistics, published-source labels, and media descriptions. Topic questions can reach later paragraphs directly, while broader questions retain their reviewed summaries. External documents are linked from their authored records; their contents were not newly fetched or indexed.

Source-only sections now appear in evidence notebooks, with the requested material expanded first. Active-section imagery uses the appropriate image, gallery image, or poster. Published quotes and media material remain reachable. Statistics already shown in the passage are not duplicated as another display of the same value.

Follow-ups such as “Show sources” and “What were his findings?” retain the active project. Explicit focus changes clear stale excerpt selections; project changes retain the chosen focus and initialize its proper section. Portable action tools follow the same rule while preserving explicitly supplied section choices. General career exploration now includes the reviewed brand, journalism, and teaching-team roles. On narrow screens, the selected career answer precedes the role choices.

Explicit compound requests can create up to three distinct authored views locally, including a project alongside a scorecard or career answer. Clause-level reconciliation prevents one subject's “learned” or “outcomes” wording from resetting another subject's evidence. Follow-ups retain unrelated companion controls. A country named only in an excluded photography clause cannot silently become a work subject.

Back and Forward restore the selected view and move keyboard focus to its heading when navigation originated inside results. Shared views preserve exact section and paragraph selections; visitor drafts and provider metadata remain outside the URL. The permanent photo gallery and album/lightbox navigation remain functional.

Backend work includes a public-ID-constrained structured-output schema, complete shared evidence catalogs, bounded upstream JSON reads, cancellation-aware waits, deadline enforcement, failed-stream cache protection, validated coverage telemetry, and an offline-by-default evaluation tool. See the [backend research and implementation review](genui-backend-2026-11-02.md) for primary sources and the provider-specific changes.

## Verification

- Full Vitest suite (**732 tests across 51 files**), ESLint, actual app and Node TypeScript checks, and production/MCP builds pass. The root typecheck command previously traversed no source projects; it now checks both referenced projects. The build still reports its existing large-chunk advisory.
- Offline authored evaluation: **22/22 routing cases** and **32/32 project/section cases**, with zero network or model requests. Paragraph-target metrics are recorded separately because the editorial target list is not an exhaustive semantic standard.
- An additional offline matrix passes **45/45 comparisons**: every pair among six projects, across contribution, process, and outcomes. This checks routing, focus, subject order, validation, and reconciliation, not live model judgment.
- Browser DOM checks pass for all 16 layouts at desktop 1440px in both themes, 320px in both themes, and 390px dark: **80 layout checks**, with no document horizontal overflow or controls escaping the response panel. These are bounds/heading checks, complemented by manual visual inspection of representative screens.
- Browser questions across all six work areas show the appropriate published passage or material links. Specific manual checks include employee volunteering communications, congressional reporters working on deadline, transcript verification, Taiwan program materials, government methods/recommendations, and Back to School.
- Manual interaction checks cover Atlas → “Show sources,” Back/Forward heading focus, shared deep-answer restoration, focus/project switching, combined project/scorecard views, deep work-search terms for all six projects, evidence navigation with search restoration, Taiwan album/lightbox navigation, and return to the 17-album gallery. Light appearance and the original browser viewport were restored.

## Review boundary

The scope follows the repository's public-content rules: six published case studies, with four explicitly hidden projects and the separate photography gallery excluded from live AI evidence. No source claims or dates were invented, no provider credentials were restored, and no live Mistral/Jev calls were made. Mocked provider contracts establish schema, catalog, and reconciliation behavior; offline selections and browser results establish authored local behavior. Neither establishes current provider availability, latency, or real model selection quality.

After reviewing and deploying, use the bounded, explicit live evaluation in [evals/README.md](../../evals/README.md) against seiler.page. The script rejects stale content versions before model-capable requests. Process-local quotas remain safeguards rather than a distributed spending cap.
